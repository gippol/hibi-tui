# hibi-tui — 日々

タスクを管理して、作業時間を記録し、その日の日報と月報を Markdown で出力する TUI アプリ。
要件は [docs/requirements.md](docs/requirements.md)。

## ビルドと配置

```powershell
# exe 1つ（自己完結・単一ファイル）を publish\hibi.exe に作る
dotnet publish src/Hibi -c Release -o publish
```

`publish\hibi.exe` を PATH の通ったフォルダに置けば、どこからでも `hibi` で起動できる。
.NET ランタイムを別に入れる必要はない。
exe を配るときは、同じフォルダにできる `LICENSE` と `THIRD-PARTY-NOTICES.txt` も一緒に配る。

開発中は `dotnet run --project src/Hibi` でも動く。

## 使い方

| キー | 操作 |
|---|---|
| ↑ / ↓ | タスクを選ぶ（見出し行は飛ばす） |
| `Shift+↑` / `Shift+↓` | 未完了タスクを並べ替える（`[今日の予定]` は日報で選んだ順なので動かさない） |
| `/` | 絞り込み。スペース区切りの語をすべて含むもの。`#名前` はプロジェクトだけで探す |
| `Esc` | 絞り込みを解除する |
| `p` | 手で保留にする / 保留から戻す（自動で保留になったものも戻せる） |
| `h` | `[保留]` を開く / たたむ |
| `a` | タスクを追加 |
| `Enter` | タイマーを開始/停止（別のタスクを開始すると前のタイマーは止まる） |
| `d` | 完了にする / 完了を取り消す（取り消しは確認あり） |
| `e` | タスクを編集（タイトル・プロジェクト・期限・優先度・メモ） |
| `t` | 作業記録を修正（テキストで編集） |
| `x` | 削除（確認あり） |
| `n` | 今日の所感を書く |
| `r` | 明日の予定を選んで日報を出力（クリップボードにもコピーする） |
| `N` / `R`（Shift） | 業務日（既定は前の日）を選んで、所感を書く / 日報を出力する（書き忘れ・出し忘れの取り戻し） |
| `w` | 日付（既定は今日）を入れて、その日を含む週（月曜〜日曜）の週報を出力 |
| `m` | 月（`yyyy-MM`、既定は今月）を入れて月報を出力 |
| `q` | 終了（タイマーは止まらない。次に起動したとき、長時間動いていたら確認する） |

前の業務日の日報で選んだ「明日の予定」は、一覧の一番上に `[今日の予定]` として出る（完了したものは出ない）。
土日などで日が空いても、いちばん最近に選んだ予定を使う。その日に何も選ばずに日報を出したら、それより前の日にはさかのぼらず予定なしになる。

`p` で手で保留にしたものと、最後に触ってから `staleTaskDays`（既定 14）業務日以上たった未完了タスクは、`[保留 N件]` にまとめてたたんでおく。
「触った」は作成・編集・保留の切り替え・完了の取り消し・作業記録（開始・終了）のこと。
保留から戻すには `p`。タイマーを始めても戻る。
計測中のものは保留にしない。`[今日の予定]` のものは自動では保留にならない（手で保留にすると `[今日の予定]` から外れる）。
絞り込み中は `[保留]` も開いて出す。

タスクには期限（`yyyy-MM-dd`）と優先度（高・普通・低）を付けられる。一覧では、高は `!`、低は `↓` をタイトルの前に付ける。
期限は `〆11-10` と出す（今日なら `〆今日`、過ぎていたら `期限切れ`）。並び順は変えない（`Shift+↑↓` の手の並びのまま）。日報などには載せない。

過去の日の日報では、「進行中」にその日の時点で完了していなかったタスクが入り、累計はその日までの時間になる。

ダイアログの中の操作：
- 1行の入力欄では `Enter` で OK
- 複数行の欄（メモ、所感、作業記録）では `Ctrl+S` で保存
- `Esc` でキャンセル
- 削除と完了の取り消しの確認は、最初から「キャンセル」が選ばれている。実行するときは `←` か `Tab` で選んでから `Enter`

### 作業記録の書き方（`t`）

```
2026-11-06 10:00 - 12:30              終了が開始より前の時刻なら翌日扱い（12時間まで）
2026-11-06 23:00 - 2026-11-07 01:00
2026-11-06 13:00 -                    計測中
```

`#` で始まる行と空行は無視する。

## ファイルの場所

| ファイル | 場所 |
|---|---|
| 設定 | `%APPDATA%\hibi\config.json`（環境変数 `HIBI_CONFIG` で差し替えられる） |
| データ | `%APPDATA%\hibi\tasks.json` |
| バックアップ | `%APPDATA%\hibi\backup\`（起動するたびに取る。7世代を残す） |
| 日報 | `%USERPROFILE%\Documents\hibi\reports\YYYY-MM-DD.md` |
| 月報 | `%USERPROFILE%\Documents\hibi\reports\YYYY-MM.md`（日報と同じフォルダ） |
| 週報 | `%USERPROFILE%\Documents\hibi\reports\YYYY-Www.md`（ISO 週番号。例: `2026-W45.md`） |

tasks.json は今 `schemaVersion: 5`。
- v2: 並び順 `order` を追加。v1 のファイルは読み込むときに作成順で並び順を振る
- v3: `updatedAt`（最後に手で変えた日時）/ `onHold`（手で保留）/ `due`（期限）/ `priority`（`high` / `normal` / `low`）を追加。v2 以前のファイルは既定値（なし・`false`・なし・`normal`）で読む
- v4: 日ごとの記録に `tomorrowChosen`（明日の予定を選んだか）を追加。v3 以前のファイルは、明日の予定が空でない日だけ選んだことにして読む
- v5: `tomorrowChosen` をやめ、選んでいない日は `tomorrowTaskIds` を `null` にする。v4 以前のファイルは、選んだ印がある日・予定が空でない日・所感もない日（日報を出した日）を選んだことにして読む

古い形のファイルは、次に保存したときに今の形で書き直す。新しい形になったファイルは古い exe では開けない（バックアップは元の形のまま残る）。

設定の項目は `dataDirectory` / `reportDirectory` / `dayBoundary`（既定 `04:00`）/ `forgottenTimerWarningHours`（既定 `8`）/ `staleTaskDays`（既定 `14`。`0` で保留を使わない）。

## 開発

```powershell
dotnet test                               # Core のテスト
publish\hibi.exe --startup-check          # 最初の描画まで行って終了し、起動時間を表示する
```

| プロジェクト | 中身 |
|---|---|
| `src/Hibi.Core` | モデル・業務日・タイマー・日報の生成・保存（UI に依存しない） |
| `src/Hibi` | Terminal.Gui v2 の TUI |
| `tests/Hibi.Core.Tests` | xUnit のテスト |
