# hibi 要件定義書

- 作成日: 2026-11-06
- バージョン: 1.0（v1 スコープ）

---

## 1. 概要

### 1.1 目的
日々のタスクを管理し、作業時間を記録して、その日の作業内容を **Markdown 形式の日報** として出力するアプリ。

### 1.2 前提
| 項目 | 内容 |
|---|---|
| 利用者 | 自分専用（1人。ログインと権限管理は作らない） |
| 利用環境 | Windows 11 の PC 1台 |
| データ | ローカル保存のみ。同期が必要になったら、保存先を OneDrive などに置いて対応する |
| 日報の位置づけ | 自分の記録用。Markdown ファイルとして残す |
| UI | TUI（ターミナル上で操作する画面） |

### 1.3 方針
- **すぐ使える**: exe 1つで動く。起動したらすぐ操作できる
- **軽い**: 起動から1秒以内に操作できる
- **正確**: 作業時間は丸めず、自分の記録として正確さを優先する

## 2. 技術構成

| 項目 | 採用 |
|---|---|
| 言語 | C#（.NET） |
| TUI ライブラリ | Terminal.Gui v2 |
| 配布形態 | `dotnet publish` で作る単一 exe |
| データ形式 | JSON |

---

## 3. 用語

| 用語 | 意味 |
|---|---|
| タスク | 管理する作業の単位 |
| 作業記録 | タイマーで計測した1回分の作業時間（開始時刻と終了時刻）。1つのタスクに何件でも付く |
| 業務日 | 日付の切り替わり時刻（既定 4:00）を基準にした1日。例: 11/7 の 2:00 は 11/6 の業務日に入る |
| プロジェクト | タスクの分類。1つのタスクに1つだけ付けられる（付けなくてもいい） |
| 所感 | 業務日ごとに書く自由コメント |
| 明日の予定 | 日報に載せる、次の業務日にやるタスクの一覧 |

---

## 4. 機能要件

### 4.1 タスク管理

| ID | 要件 |
|---|---|
| F-T-01 | タスクを追加できる。タイトルは必須、プロジェクトとメモは任意 |
| F-T-02 | タスクのタイトル・プロジェクト・メモを編集できる |
| F-T-03 | タスクを削除できる（確認ダイアログを出す） |
| F-T-04 | タスクの状態は **未着手 / 作業中 / 完了** の3つ |
| F-T-05 | タスクを完了にできる。そのとき完了日時を記録する。タイマーが動いていれば止める |
| F-T-06 | 完了を取り消して未完了に戻せる。完了日時は消す |
| F-T-07 | 完了したタスクは、その業務日のあいだ「今日の完了」に表示する。次の業務日になったら一覧から消す（データは残す） |
| F-T-08 | メモは自分用の詳細で、日報には載せない |

### 4.2 作業時間の記録

| ID | 要件 |
|---|---|
| F-W-01 | 選んだタスクのタイマーを開始・停止できる |
| F-W-02 | 同時に計測できるのは1つだけ。別のタスクを開始したら、動いていたタイマーは自動で止める |
| F-W-03 | タイマーを開始したタスクは「作業中」になる。止めたら「未着手」には戻さず、作業記録があるタスクとして未完了の一覧に残す（表示上は「作業中」マークを外す） |
| F-W-04 | 1分未満の計測は記録しない（すぐ止めたものは捨てる） |
| F-W-05 | 作業記録をあとから手で修正できる（開始時刻・終了時刻の変更、追加、削除） |
| F-W-06 | タイマーの開始時刻は保存しておく。アプリを閉じても計測を続ける |
| F-W-07 | 起動したとき、タイマーが **警告する時間（既定 8時間）以上** 動いていたら「止め忘れていませんか？」と聞く。そのまま続けるか、終了時刻を入れて止めるかを選べる |
| F-W-08 | 作業記録は **開始時刻の業務日** に入れる |

> F-W-03 補足: 状態は「未着手（作業記録がない）」「作業中（タイマーが動いている）」「完了」の3つ。タイマーを止めた未完了タスクは、データ上は「未完了」として扱い、作業記録があるかないかで表示を分ける。

### 4.3 所感

| ID | 要件 |
|---|---|
| F-N-01 | 業務日ごとに所感を TUI の入力欄で書ける（複数行） |
| F-N-02 | 所感はアプリのデータとして保存する。日報を作り直しても消えない |

### 4.4 日報の出力

| ID | 要件 |
|---|---|
| F-R-01 | TUI のキー操作で、今の業務日の日報をいつでも出力できる |
| F-R-02 | 出力するときに **明日の予定を選ぶダイアログ** を出す。未完了のタスクをチェックリストで並べる |
| F-R-03 | 選んだ明日の予定は業務日ごとに保存する。作り直すときは前回の選択にチェックが入った状態で出す |
| F-R-04 | ダイアログからその場で新しいタスクを追加できる。追加したタスクにはチェックが入った状態にする |
| F-R-05 | 出力先は `<日報フォルダ>\YYYY-MM-DD.md`（業務日の日付）。同じ日に作り直すと上書きする |
| F-R-06 | 出力したら、保存先のパスを画面に表示する |
| F-R-07 | 出力した日報の Markdown を、クリップボードにもコピーする（v1 のあとに追加）。ファイルに保存できなかったときもコピーする。コピーできたかどうかを画面に表示する。コピーできなくても出力は止めない |

#### 4.4.1 日報に載せる内容

| 欄 | 載せるもの |
|---|---|
| 稼働合計 | その業務日の作業記録をすべて合計した時間 |
| 完了 | その業務日に完了にしたタスク |
| 進行中 | その業務日に作業記録があって、まだ完了していないタスク |
| 明日の予定 | F-R-02 で選んだタスク |
| 所感 | その業務日の所感 |

- 完了と進行中のタスクには **その日の作業時間** と **累計の作業時間** を書く
- その後ろに、その日の作業記録の **時間帯** を開始の順に `09:00〜10:30, 13:00〜14:15` の形で書く（v1 のあとに追加）。時刻は記録したときの時計のままで、切り替わり時刻を過ぎた深夜は `23:30〜01:00` のように書く。計測中は `13:00〜` と終了を空ける。月報・週報には書かない
- 完了と進行中は **プロジェクトごと** にまとめる。プロジェクトがないタスクは「その他」に入れる
- その業務日に作業記録がない未完了タスクは載せない（明日の予定に選んだものは除く）
- 空の欄は「なし」と書く

#### 4.4.2 テンプレート（v1 では固定）

```markdown
# 日報 2026-11-06（金）

稼働合計: 6h45m

## 完了
### backend
- DBマイグレーション — 1h30m（累計 3h00m）09:00〜10:30
### frontend
- ヘッダー修正 — 0h40m（累計 0h40m）11:00〜11:40

## 進行中
### backend
- API修正 — 2h15m（累計 4h10m）13:00〜14:00, 15:00〜16:15

## 明日の予定
- API修正
- ログイン画面

## 所感
（TUIで書いた内容）
```

- プロジェクトは名前の順に並べ、「その他」は最後に置く
  - アルファベットは大文字小文字を区別せずに並べる（`alpha` → `Beta` → `Zeta`）
  - 漢字・かなは文字コード順（五十音順にはならない）
  - 大文字小文字だけ違う名前（`Backend` と `backend`）は別のプロジェクトとして扱い、大文字のほうを先に置く
- 同じプロジェクトの中は、完了は完了日時の順、進行中はその日最初に作業を始めた順に並べる

#### 4.4.3 時間の表示

- 形式は `XhYYm`（例: `0h40m`, `12h05m`）
- 分未満は **切り捨て**。15分単位などの丸めはしない
- 合計を出すときは秒単位で足してから切り捨てる

### 4.5 業務日

| ID | 要件 |
|---|---|
| F-D-01 | 業務日は **日付の切り替わり時刻（既定 4:00）** で区切る |
| F-D-02 | 切り替わり時刻は設定で変えられる |
| F-D-03 | アプリを開いたまま切り替わり時刻を過ぎたら、一覧（今日の完了など）を新しい業務日の内容に更新する |

### 4.6 月報の出力

| ID | 要件 |
|---|---|
| F-M-01 | TUI のキー操作（`m`）で、指定した月の月報を出力できる |
| F-M-02 | 出力するときに対象の月（`yyyy-MM`）を入れるダイアログを出す。最初は今の業務日の月が入っている |
| F-M-03 | 月の範囲は **業務日** の1日〜末日。例: 12/1 の 3:00 に始めた作業は 11/30 の業務日なので 11月に入る |
| F-M-04 | 出力先は `<日報フォルダ>\YYYY-MM.md`。同じ月を作り直すと上書きする |
| F-M-05 | 出力したら、保存先のパスを画面に表示する |

#### 4.6.1 月報に載せる内容

| 欄 | 載せるもの |
|---|---|
| 期間・稼働合計 | 月の1日〜末日、その月の作業記録の合計、作業記録があった日数 |
| プロジェクト別 | プロジェクトごとの、その月の作業時間 |
| 完了 | その月に完了にしたタスク |
| 進行中 | その月に作業記録があって、その月のうちには完了していないタスク（翌月以降に完了したものも含む） |
| 日別 | 作業記録があった日ごとの作業時間 |
| 所感 | その月の各業務日の所感（書いた日だけ） |

- 完了と進行中には **その月の作業時間** と **累計の作業時間** を書く。並べ方は日報（4.4.2）と同じ。プロジェクト別の欄のプロジェクトも同じ順に並べる
- 累計は **月の末日（業務日）までの合計**。あとから作り直しても、翌月以降の作業で数字は変わらない
- 時間の表示は 4.4.3 と同じ。空の欄は「なし」と書く

```markdown
# 月報 2026-11

期間: 2026-11-01（日） 〜 2026-11-30（月）
稼働合計: 5h00m（稼働 4日）

## プロジェクト別
- backend — 4h15m
- frontend — 0h40m
- その他 — 0h05m

## 完了
### backend
- DBマイグレーション — 1h30m（累計 2h30m）

## 進行中
### backend
- API修正 — 2h45m（累計 3h45m）

## 日別
- 11-05（木） — 1h30m
- 11-06（金） — 2h20m

## 所感
### 11-06（金）
（TUIで書いた内容）
```

### 4.7 週報の出力（v1 のあとに追加）

| ID | 要件 |
|---|---|
| F-K-01 | TUI のキー操作（`w`）で、指定した週の週報を出力できる |
| F-K-02 | 出力するときに日付（`yyyy-MM-dd`）を入れるダイアログを出す。その日を含む週が対象。最初は今の業務日が入っている |
| F-K-03 | 週は **業務日** の月曜〜日曜 |
| F-K-04 | 出力先は `<日報フォルダ>\YYYY-Www.md`（ISO 8601 の週番号。年をまたぐ週は ISO の年を使う）。同じ週を作り直すと上書きする |
| F-K-05 | 出力したら、期間と保存先のパスを画面に表示する |

- 載せる内容・並べ方・時間の表示は月報（4.6.1）と同じ。見出しは `# 週報 2026-W45`

### 4.8 保留（v1 のあとに追加）

| ID | 要件 |
|---|---|
| F-H-01 | 最後に触ってから `staleTaskDays`（既定 14）業務日以上たった未完了タスクを「保留」として、一覧の `[保留 N件]` にまとめる（自動の保留） |
| F-H-02 | 「最後に触った日」は、作成日時・更新日時（`updatedAt`）・作業記録の開始と終了のうち、いちばん新しいものの業務日。更新日時は、編集・保留の切り替え・完了の取り消しで記録する |
| F-H-03 | 計測中のタスクは保留にしない。`[今日の予定]` のタスクは自動では保留にしない。完了したタスクは対象外 |
| F-H-04 | 自動の保留はデータに保存せず、表示するたびに決める。触れば自動で `[未完了]` に戻る |
| F-H-05 | `[保留]` はふだんたたんでおき、`h` で開く・たたむ。絞り込み中は開いて出す |
| F-H-06 | 詳細に「最後に触った日（N日前）」と、保留の理由（手で保留 / 長く触っていない）を出す |
| F-H-07 | `p` で手で保留にできる（`onHold` に保存する）。`staleTaskDays` が 0 でも効く。手で保留にしたものは `[今日の予定]` に出さない |
| F-H-08 | 保留（手・自動どちらも）のタスクで `p` を押すと戻す。戻すと「触った」ことになる。タイマーを始めても手の保留は外れる |
| F-H-09 | 計測中のタスクと完了したタスクは、手でも保留にできない |

### 4.9 期限・優先度（v1 のあとに追加）

| ID | 要件 |
|---|---|
| F-P-01 | タスクに期限（業務日。`yyyy-MM-dd`。なくてもよい）と優先度（高・普通・低。既定は普通）を付けられる。追加・編集のダイアログで入れる |
| F-P-02 | 一覧では、優先度が高いものはタイトルの前に `!`、低いものは `↓` を付ける |
| F-P-03 | 未完了タスクの期限を一覧に `〆MM-dd` で出す。今の業務日なら `〆今日`、過ぎていたら `期限切れ` を付ける |
| F-P-04 | 詳細に優先度と期限（曜日つき）を出す |
| F-P-05 | 並び順は変えない（手の並べ替えのまま）。日報・週報・月報には載せない |

## 5. 画面とキー操作

### 5.1 メイン画面

```
┌ hibi ─────────────── ▶ 作業中: API修正 00:42:15 ┐
│ [未完了]                    │ 詳細                       │
│ ▶ API修正        #backend   │ タイトル: API修正          │
│   ログイン画面    #frontend  │ プロジェクト: backend       │
│ [今日の完了]                 │ 今日: 0h42m / 累計: 3h10m  │
│ ✓ DBマイグレーション #backend │ メモ: ...                  │
├─────────────────────────────┴───────────────────────────┤
│ a:追加 Enter:開始/停止 d:完了 e:編集 t:時間修正 x:削除     │
│ n:所感 r:日報出力 q:終了                                  │
└──────────────────────────────────────────────────────────┘
```

| 場所 | 表示するもの |
|---|---|
| ヘッダー | アプリ名。作業中のタスク名と経過時間（毎秒更新） |
| 左: タスク一覧 | 「未完了」と「今日の完了」の2つに分けて表示する。作業中のタスクには ▶、完了には ✓ を付ける |
| 右: 詳細 | 選んでいるタスクのタイトル、プロジェクト、今日の作業時間、累計の作業時間、メモ |
| フッター | キー操作のヘルプ |

### 5.2 キー操作

| キー | 操作 |
|---|---|
| ↑ / ↓ | タスクを選ぶ |
| `a` | タスクを追加する（ダイアログ） |
| `Enter` | タイマーを開始・停止する |
| `d` | 完了にする / 完了を取り消す |
| `e` | タスクを編集する（ダイアログ） |
| `t` | 作業記録を修正する（ダイアログ） |
| `x` | タスクを削除する（確認あり） |
| `n` | 所感を書く（ダイアログ） |
| `r` | 日報を出力する（明日の予定を選ぶダイアログ → 出力） |
| `m` | 月報を出力する（月を入れるダイアログ → 出力） |
| `q` | 終了する（タイマーは止めない。F-W-06） |

> 細かいところは実装しながら調整する。

### 5.3 ダイアログ

| ダイアログ | 入力するもの |
|---|---|
| タスクの追加・編集 | タイトル（必須）、プロジェクト（既存のものから選ぶか新しく入力する。空でもいい。既存の一覧は 4.4.2 と同じ順に並べる）、メモ（複数行） |
| 作業記録の修正 | そのタスクの作業記録の一覧。開始時刻・終了時刻の編集、追加、削除 |
| 所感 | 今の業務日の所感（複数行） |
| 明日の予定 | 未完了タスクのチェックリスト、新しいタスクの追加、出力の確定 |
| 止め忘れの確認 | 続ける / 終了時刻を入れて止める |

## 6. データ

### 6.1 保存場所

| ファイル | 既定のパス |
|---|---|
| タスクデータ | `%APPDATA%\hibi\tasks.json` |
| 設定 | `%APPDATA%\hibi\config.json` |
| バックアップ | `%APPDATA%\hibi\backup\tasks.YYYYMMDD-HHmmss.json` |
| 日報 | `%USERPROFILE%\Documents\hibi\reports\YYYY-MM-DD.md` |
| 月報 | `%USERPROFILE%\Documents\hibi\reports\YYYY-MM.md` |

### 6.2 tasks.json の構造（案）

```json
{
  "schemaVersion": 3,
  "tasks": [
    {
      "id": "0b9c...（GUID）",
      "title": "API修正",
      "project": "backend",
      "memo": "エラー時のレスポンス形式を統一する",
      "order": 0,
      "createdAt": "2026-11-05T10:12:00+09:00",
      "updatedAt": "2026-11-06T09:00:00+09:00",
      "onHold": false,
      "due": "2026-11-10",
      "priority": "high",
      "completedAt": null,
      "workLogs": [
        { "start": "2026-11-05T10:15:00+09:00", "end": "2026-11-05T12:00:00+09:00" },
        { "start": "2026-11-06T13:00:00+09:00", "end": null }
      ]
    }
  ],
  "days": {
    "2026-11-06": {
      "note": "所感のテキスト",
      "tomorrowTaskIds": ["0b9c..."]
    }
  }
}
```

- `end` が `null` の作業記録が、今動いているタイマー。全体で1件までしかない
- 状態は保存せず、`completedAt` と `workLogs` から決める
  - `completedAt` が入っている → 完了
  - 終わっていない作業記録がある → 作業中
  - どちらでもない → 未完了
- `schemaVersion` は、あとでデータの形を変えるとき（マイグレーション）に使う
  - 2: `order`（並び順。小さいほど上。全タスクで通し番号）を追加。v1 は作成順で振る
  - 3: `updatedAt`（null 可）/ `onHold` / `due`（null 可）/ `priority`（`high` / `normal` / `low`）を追加。v2 以前は既定値で読む

### 6.3 config.json

```json
{
  "dataDirectory": "%APPDATA%\\hibi",
  "reportDirectory": "%USERPROFILE%\\Documents\\hibi\\reports",
  "dayBoundary": "04:00",
  "forgottenTimerWarningHours": 8,
  "staleTaskDays": 14
}
```

| 項目 | 意味 | 既定値 |
|---|---|---|
| `dataDirectory` | tasks.json とバックアップを置くフォルダ | `%APPDATA%\hibi` |
| `reportDirectory` | 日報を出力するフォルダ | `%USERPROFILE%\Documents\hibi\reports` |
| `dayBoundary` | 業務日の切り替わり時刻 | `04:00` |
| `forgottenTimerWarningHours` | 止め忘れを警告するまでの時間 | `8` |
| `staleTaskDays` | この業務日数のあいだ触っていない未完了タスクを保留にする（4.8）。`0` なら使わない | `14` |

- config.json がなければ、既定値で作る
- パスの中の環境変数（`%APPDATA%` など）は展開して使う
- フォルダがなければ自動で作る

## 7. 非機能要件

### 7.1 性能
| ID | 要件 |
|---|---|
| N-P-01 | 起動から操作できるまで **1秒以内** |
